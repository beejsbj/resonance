# Resonance agent router

Resonance is still in wayfinding. Linear holds live work; this repository holds settled context and playable evidence.

- **Product work:** read [docs/product-brief.md](docs/product-brief.md) and [CONTEXT.md](CONTEXT.md) before changing mechanics, progression, fiction, or vocabulary. Update them only when a decision settles.
- **Wayfinding, specification, or tickets:** read [docs/agents/wayfinding-entry.md](docs/agents/wayfinding-entry.md), [docs/agents/sessions.md](docs/agents/sessions.md), and [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md). Use BJS-417 as the canonical map.
- **Prototype work or evaluation:** read [docs/prototype.md](docs/prototype.md). Preserve its role as evidence.
- **Game build:** read [docs/game.md](docs/game.md) before changing `public/play/`. It lists which mechanics are provisional calls rather than settled decisions. Run `npm test` and `npm run balance` after rule or number changes.
- **Workshop and preview hosting:** push code to the Resonance GitHub repository and use Vercel previews. Burooj explicitly rejected ChatGPT Sites for this project, especially the visual workshop; the existing `.openai/hosting.json` is legacy configuration, not authorization to publish there.

Keep recruitment, arrangement, musical development, instrument identity, and conductor powers distinct in both language and code. Put unresolved work in Linear issues rather than a Markdown status list. Commit coherent checkpoints with the checks that establish what each checkpoint proves.
